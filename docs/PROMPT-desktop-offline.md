# برومبت — نسخة Desktop أوفلاين لمدرسة السليمانية

الصق هذا النص بالكامل في المحادثة لما تكون جاهز تبدأ (بعد ~أسبوع أو متى ما طلبت).

---

## المطلوب

ابنِ نسخة **سطح مكتب لويندوز** من نظام مدرسة السليمانية الحالية، مع عمل أوفلاين ومزامنة عند توفر النت.

المسار الحالي للمشروع (عدّله إذا تغيّر):
`/Users/ma7moudos/Downloads/alsulaimaniyaschool (1)`

التقنية الحالية: React + Vite + Firebase (Auth / Firestore / Functions / Storage)، منشور على Vercel، مشروع Firebase: `burouto`.

## القرار التقني المطلوب

ابدأ بـ **Electron أو Tauri** (اختر الأنسب بعد فحص سريع للمشروع؛ المفضّل إن كان أخف وأسهل للبناء على ويندوز مع نفس كود Vite):

- نفس كود الواجهة تقريباً (لا تعيد بناء النظام من الصفر)
- تجربة Desktop على ويندوز (تثبيت / تشغيل كبرنامج)
- تفعيل **Firestore Offline Persistence** للعمل بدون نت بعد أول تحميل/مزامنة
- مزامنة تلقائية لما يرجع النت (سحب + رفع التعديلات)
- قائمة واضحة داخل الواجهة للعمليات التي **تحتاج نت** ولا تعمل أوفلاين

## عمليات تحتاج نت (لازم تظهر بوضوح للمستخدم أوفلاين)

على الأقل:
- إنشاء/دعوة مستخدمين وكلمات المرور
- قبول طلبات التسجيل التي تعتمد Cloud Functions
- النسخ الاحتياطي / الاستيراد / مسح النظام (`/admin/backup`)
- تسجيل الدخول لأول مرة (أو عند انتهاء الجلسة)
- أي Callable Functions أخرى (رواتب تصدير، إلخ حسب الموجود)

أوفلاين يفضّل أن يعمل لـ:
- تصفح وتعديل بيانات Firestore المحمّلة مسبقاً (طلاب، صفوف، فواتير معروضة محلياً…)
- التنقّل بين لوحات الأدوار بعد تسجيل دخول سابق محفوظ

## نطاق المرحلة الأولى (MVP)

1. تغليف التطبيق الحالي كـ Desktop (Windows)
2. تفعيل offline persistence لـ Firestore بشكل صحيح في بيئة Desktop
3. مؤشر حالة الاتصال في الواجهة: متصل / غير متصل / جاري المزامنة
4. تعطيل أو رسالة واضحة على الأزرار التي تحتاج نت عند الأوفلاين
5. تعليمات بناء ملف تشغيل/تثبيت ويندوز (مثلاً `.exe` أو installer)
6. لا تكسر نسخة الويب على Vercel — نفس الريبو إن أمكن (مجلد desktop أو إعدادات مشتركة)

## خارج النطاق الآن (إلا إذا طلبت لاحقاً)

- إعادة بناء قاعدة بيانات محلية كاملة (SQLite) من الصفر
- مزامنة مخصصة معقدة خارج آلية Firestore
- دعم macOS/Linux في المرحلة الأولى (ويندوز أولاً)

## أسلوب التنفيذ

- افحص المشروع أولاً ثم نفّذ بأقل تغيير يكسر الويب
- التزم بأسلوب الكود الحالي (Arabic RTL، نفس المكوّنات)
- بعد التنفيذ: خطوات تشغيل محلي + بناء ويندوز + ماذا يعمل أوفلاين وماذا لا
